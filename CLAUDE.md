# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static monorepo of OPS Tech HTML slide decks published to GitHub Pages
(<https://ops-pivers.github.io/ops-presentations/>). **No build step, no package
manager, no framework, no server.** Every presentation is a folder containing one
`index.html` plus `media/`; the `<deck-stage>` engine and the OPS brand layer are
shared at the repo root and referenced with relative `../` paths.

There is no test suite, linter, or CI. Verification is visual: serve the deck,
arrow through it, and check print/reduced-motion.

## Commands

Decks load media via `fetch`, so they must be served over HTTP — `file://` breaks them:

```bash
npx serve .
```

Then open `http://localhost:<port>/<deck-slug>/`.

- **Kiosk / self-running:** append `?kiosk` (or `?autoplay`) to the deck URL.
- **PDF:** browser Print → Save as PDF gives one slide per page (`@media print`
  is handled by the engine).
- **Keys while presenting:** →/← advance, `T` rail, `A` manual↔autobuild, `R` reset.

## Architecture

```
index.html      landing page — the DECKS registry array drives everything
_framework/     the engine (shared, seeded verbatim from canonical source)
_brand/         OPS Tech design layer (tokens, archetypes, motion, poll config)
<deck-slug>/    one folder per deck: index.html + media/
poll-backend/   Apps Script source for live polls — NOT served; deployed once
```

**`_framework/`** is a set of vanilla web components loaded as plain `<script>` tags:

| File | Role |
|---|---|
| `deck-stage.js` | `<deck-stage>` — auto-scaling 1920×1080 canvas, thumbnail rail, presenter view, print layout, speaker notes, reveal/build pacing. Slides are its direct element children. |
| `media-slot.js` | `<media-slot>` — video/GIF/image placeholder; drag-drop persists to **IndexedDB** (per-browser, does *not* travel with the file). `src` is what ships on the static host. |
| `image-slot.js` | `<image-slot>` — image placeholder with double-click crop/reframe; persists to a `.image-slots.state.json` sidecar (gitignored, omelette-runtime only). |
| `media-lightbox.js` | Click-to-enlarge modal for any filled slot; `gallery="a \| b \| c"` pages a carousel. |
| `live-poll.js` | `<live-poll>` — polls the Apps Script backend only while its slide is active. |

**`_brand/`** splits three ways, and the split matters when deciding where CSS goes:

- `colors_and_type.css` — design tokens (`--ot-blue`, `--fg-*`, type scale, spacing).
- `slides.css` — the shared **slide archetypes** (`.s`, `.navy`/`.light`, `.cover`,
  `.statement`, `.grid3`, `.demo`, …) plus slide-frame variables with 1920×1080
  defaults, plus the base reveal idiom.
- `motion.css` + `MOTION.md` — the expressive motion vocabulary and the
  `data-motion` intensity knob.

A deck's inline `<style>` overrides only slide-frame variable *values* and
talk-specific tuning (a one-off font size, an `aspect-ratio` matched to a
specific recording). Reusable patterns belong in `slides.css`.

## Hard rules

**Never regenerate `_framework/`.** It is seeded byte-for-byte from the canonical
source. Local changes go *only* inside the `/* === OPS EXTENSION … === */` banners
in `deck-stage.js` (currently: named reveal modes, rail styling).

**The animation contract.** Every animated class makes its **visible end-state the
resting/base style** and animates *from* hidden — only non-active slides pre-hide,
gated on `[data-deck-active]`, wrapped in `@media (prefers-reduced-motion:
no-preference)`, and guarded with `:not([noscale])`. No infinite loops. This
single invariant is why print, reduced-motion, the image/PPTX exporter (which
renders at `noscale`), and the rail thumbnails all show the finished slide. A
class that hides content at rest prints blank.

**Never set `position` / `inset` / `width` / `height` on a slide `<section>`** —
`<deck-stage>` absolutely-positions and scales every slide itself.

**Write slides as static HTML**, not generated by a script or a loop over a JS
array. Static markup is what lets a human click a heading and retype it. Reach
for script-generated slides only when the content genuinely needs interactivity.

**One speaker note per slide, in slide order**, in the
`<script type="application/json" id="speaker-notes">` array at the end of `<body>`.

## Deck authoring

Load order in `<head>`: `colors_and_type.css` → `slides.css` → `motion.css`.
Scripts at the end of `<body>`: `image-slot.js`, `media-slot.js`,
`media-lightbox.js`, `deck-stage.js` (and `../_brand/poll-config.js` *before*
`../_framework/live-poll.js` if the deck has a poll).

**Reveal modes** (`<deck-stage reveal="…">`): `manual` (default, speaker reveals
each beat), `autobuild` (self-running build, speaker still advances slides),
`kiosk` (`?kiosk`/`?autoplay` or `reveal="auto"` — build *and* auto-advance). The
`A` key flips manual↔autobuild live and is deliberately **not persisted**.

**Build beats in manual mode:** beat 0 is the header block (`.anim`/`.title`/
`.grow-x`), then each outermost `.cascade` and each standalone `.anim3` in
document order. Override with `data-build="step|arrival|skip"` or
`data-build-group`.

**Per-slide hooks:** `data-label` (rail label), `data-pin-hero`/`data-pin-hide`
(corner badge), `data-deck-skip` (omit from nav/print).

**Motion intensity:** `data-motion="calm|standard|lively"` on `<deck-stage>`,
chosen by the deck's audience. See `_brand/MOTION.md`.

Ship media slots **empty** with a descriptive `placeholder` and the right aspect
ratio unless the media already exists.

## Registering a deck

A deck is invisible until it is added to the `DECKS` array in the root
`index.html`, above the `── ADD NEW DECKS ABOVE THIS LINE ──` marker:

```js
{ slug, title, type, audience, date, desc }
```

`type` and `audience` each take a string *or* an array; every value becomes a
filter option and a card chip. `AUDIENCE_ORDER` / `TYPE_ORDER` only set menu
display order — they are not whitelists. Cards de-dupe by slug at render, so
re-adding is a no-op. **Slugs are URLs — keep them stable.**

## The html-slide-deck skill

`.claude/skills/html-slide-deck/` is version-controlled *with* the repo (the
`.gitignore` ignores `.claude/*` but un-ignores `.claude/skills/`). It builds decks
by composing a **structure** (purpose — slide sequence and partials) with an
**audience** (who — tone, theme, density, motion intensity). Precedence on
conflict: audience wins tone/theme/density/motion; structure wins sequence/
partials/narrative. Default audience is `internal/staff`.

`.agents/skills/` is a byte-identical, model-agnostic mirror of `.claude/skills/`.
**Any edit to one must be applied to the other** — they are currently identical
and diverging silently is the failure mode.

The skill defers all brand judgment to the separate `ops-brand-guidelines` skill
and its DESIGN.md; don't improvise OPS brand values here.

## Live polls

`<live-poll>` needs the one-time Apps Script deploy in `poll-backend/` (see its
README) and the `/exec` URL in `_brand/poll-config.js` — that one line is the only
thing that changes after deploying. `poll-backend/` is source only and is not
served. Never commit a `reset-token="…"` into a deck.

## Media

Web-optimized `.webp`/`.mp4` copies are tracked; heavy original sources are
gitignored **per deck** via explicit patterns at the bottom of `.gitignore`. A new
deck's heavy sources need their own patterns added there.
